Start from an example — no AI needed

Don't have ChatGPT or Claude? Copy a working template, change the words and settings in your browser, and submit it for review. All you need is a free GitHub account.

The whole process: pick a starter → copy it into your own folder on GitHub → edit it in the browser → open a pull request → the validate check and a reviewer help you fix anything → SkillSimm test-runs and publishes it → you (or anyone) set up a run.

1Pick a starter

Both starters are copies of templates that run on SkillSimm today. They show the range: a five-person executive team with private information and an AI coach, and a two-seat working session where one seat is an AI agent.

Browse them on GitHub: team-decision-starter · session-desk-starter. Each folder's README lists every feature and the exact setting behind it.

2Copy it into your own folder

  1. Sign in to GitHub and open the repository. Click Fork → Create fork. You now have your own copy.
  2. On your fork, press the . key (or change github.com to github.dev in the address bar). An editor opens in your browser.
  3. In the file list on the left, right-click examples/team-decision-starter (or session-desk-starter) → Copy. Right-click the templates folder → Paste.
  4. Right-click the pasted folder → Rename. Use a short name in lowercase with hyphens, such as hospital-discharge-team. This is your slug.

Prefer working offline? Click Code → Download ZIP, copy the starter folder, edit the files in any text editor, then on your fork use Add file → Upload files and drag your folder into templates/.

3Edit it, one part at a time

A template is a folder of plain text files. template.json holds the settings for the whole simulation; each file in stages/ is one stage of work; materials/ holds what people read; skills/ holds the AI coach's instructions. Edit only the text between quotes, and keep every comma, bracket and quote mark in place. The check in step 4 points to any you break.

a. Name and describe it — template.json

"template_id": "hospital_discharge_team",    ← your slug, with _ instead of -
"name": "Hospital Discharge · Care Team + AI",
"version": "1.0.0",
...
"metadata": {
  "domain": "healthcare",
  "difficulty": "intermediate",
  "duration_minutes": 45,
  "author": "Your name",
  "learning_goals": ["…", "…"]
}

b. Seats — who takes part

team_size is the number of seats. Each seat has a number (1, 2, 3 …), a title and a goal in lens_assignments. Every task says which seat does it with participant_slot. 

"lens_assignments": [
  { "member_slot": 1, "lens": "Chief Financial Officer (CFO)",
    "goal": "What test does a new Shack have to pass?" },
  ...
]

Changing the number of seats? Also update staffing.allowed_sizes (team sizes you'll accept), staffing.human_seat_order (which seat a person gets first; the starter seats the CEO first, so one person plays the CEO), and any audience.slots and target_slots that name a seat.

c. Stages and questions — stages/*.json

Files run in name order (01_…, 02_…). A stage starts after the stages in its dependencies are done. Each task is one card a person fills in: 

{
  "task_id": "financial_decision",          ← unique, no spaces
  "participant_slot": 1,                     ← seat 1 (CFO) does this
  "name": "CFO · Unit economics",
  "type": "human",
  "hitl_prompt": "What test does a new Shack have to pass?",
  "required_fields": ["financial_decision"],
  "field_schema": {
    "financial_decision": {
      "type": "select",
      "label": "What test does a new Shack have to pass?",
      "options": ["…", "…", "…", "…"],
      "required": true
    }
  },
  "evaluation_point": true,                  ← scored?
  "evaluation_weight": 0.1                   ← share of the total score
}

Answer types you can use in field_schema:

typeThe person…Example in
selectpicks one optionteam decision, stages 1–3
multi_selectpicks any number of options—
textareawrites a paragraphCEO reason; session desk forms
text / numbertypes a short answer or a number—
likertrates on a scale (scale, min_label, max_label)team decision survey

For a ranking, use one select per position with the same options (see 03_priority_ranking.json). For an unscored survey at the end, give the stage "stage_kind": "survey_post" (see 99_post_survey.json).

d. Materials — what people read

Put files in materials/ and list each one in template.json → materials. Markdown (.md), PDF, HTML, plain text and CSV all work. Add audience to make a file private to some seats; leave it out to share with everyone. 

{ "name": "CFO — Private Briefing",
  "path": "materials/1_cfo_briefing.md",
  "mime": "text/markdown",              ← application/pdf for a PDF
  "visibility": "all_stages",
  "audience": { "slots": [1] } }        ← only seat 1 can open it

Spreading facts across private briefings is what makes people talk to each other. In the team decision starter, every Stage 1 question needs one fact from each of two colleagues.

e. AI help — on, off, or somewhere between

SettingWhereWhat it does

f. Grading

Mark scored tasks with evaluation_point: true and an evaluation_weight, and describe what a good answer looks like in evaluation/rubric.json. For a template with no scoring, set every evaluation_point to false and metadata.scoring_type to "none", as the session desk does.

Keep answer keys out of the pull request. This repository is public, so anyone can read what you commit. Put placeholders where keys would go and send the real keys to your reviewer privately; SkillSimm adds them when it sets up your template. evaluation/reference_decisions.example.json shows the shape.

4Submit it and fix what the check finds

  1. In github.dev, open Source Control (the branch icon on the left), type a short message such as Add hospital-discharge-team, and click Commit & Push.
  2. Go back to your fork on github.com. Click Contribute → Open pull request, describe your simulation, and submit.
  3. The validate check runs on your pull request. (The first time, a maintainer may need to approve it before it runs.) If it fails, click Details: each line names the file and what to fix, for example participant_slot 7 is outside seats 1–5 or not valid JSON (line 12 …) — check for a missing comma.
  4. Fix it in github.dev on your fork and push again. The pull request updates by itself.

Then a reviewer reads it for clear instructions, sound step logic, honest grading, safety and originality, and SkillSimm does a test run. Once you've agreed royalty terms, the template is published to the library with your name on it. Nothing publishes without human review.

Set up and run a simulation

Once a template is in the SkillSimm library (yours, a starter, or any published one), anyone with a SkillSimm account can run it:

  1. Sign in at app.skillsimm.com and open Library to find the template.
  2. Create a run. Choose Create New Run, select the template, and give the run a title.
  3. Shape the teams. Set People per team (within the template's allowed sizes) and Number of teams. Under Seats, each seat can be a person, an AI teammate, or your own agent. Optionally upload an email list to reserve seats for named people, or keep teams from an earlier run.
  4. Invite people. On the run page, share the Join Code, the join link or the QR code. People join with the code and are placed in teams. Add observers with the read-only observer link.
  5. Start the run. Teams can start below full size; empty seats are covered as the template says (for the team decision starter, the CEO picks up their tasks).
  6. Watch and help. Open each team's desktop to follow progress. Facilitators are alerted when a team is stuck, and can take over or reassign a task.
  7. End and review. End the run, then open its summary and reports for scores, decisions and survey answers, and export the results.

For the session desk, step 4 is different: each AI agent session joins with the run's join code from the computer it runs on, and you admit it on the run page. The run page shows the commands.

Have an AI agent after all? The structured report path lets Claude or ChatGPT build the template from a four-section description. Field-by-field reference: template format.
